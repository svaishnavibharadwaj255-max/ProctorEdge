
COMPUTER NETWORKS – REFERENCE KNOWLEDGE CHAPTER

1. OSI 7-LAYER MODEL

The Open Systems Interconnection (OSI) model is a conceptual framework that explains how data travels between devices over a network. It consists of seven layers.

1. Physical Layer: Transmits raw bits through cables, radio waves and optical fibre.
2. Data Link Layer: Provides node-to-node delivery using frames and MAC addresses. It performs error detection.
3. Network Layer: Handles logical addressing and routing using IP addresses.
4. Transport Layer: Provides process-to-process communication using TCP and UDP.
5. Session Layer: Establishes, manages and terminates communication sessions.
6. Presentation Layer: Handles data translation, encryption, decryption and compression.
7. Application Layer: Provides network services to applications through protocols such as HTTP, FTP, SMTP and DNS.

During encapsulation, each layer adds control information to data. At the receiver, decapsulation removes this information.

2. NETWORK LAYER – LOGICAL ADDRESSING AND ROUTING

The Network Layer manages logical addressing, routing and packet forwarding between networks.

IP Addressing:
An IP address identifies a device on a network.
- IPv4 uses a 32-bit address, such as 192.168.1.10.
- IPv6 uses a 128-bit address, such as 2001:db8::1, providing a much larger address space.

CIDR (Classless Inter-Domain Routing) represents network prefixes using slash notation. For example, 192.168.1.0/24 means the first 24 bits identify the network portion.

Routing:
Routing selects a path for packets to travel from source to destination. Routers examine the destination IP address and consult routing tables to choose the next hop or outgoing interface.

TTL (Time To Live):
IPv4 routers decrease the TTL value as a packet travels. When it reaches zero, the packet is discarded. IPv6 uses a Hop Limit field for the same purpose. This prevents packets from circulating indefinitely in routing loops.

3. TRANSPORT LAYER – TCP AND UDP

The Transport Layer provides communication between applications on different devices. TCP and UDP use port numbers to identify application processes.

TCP (Transmission Control Protocol):
TCP is connection-oriented and provides reliable, ordered data delivery.

It establishes connections using a three-way handshake:
1. SYN: The client requests a connection.
2. SYN-ACK: The server acknowledges the request.
3. ACK: The client confirms the connection.

TCP uses sequence numbers, acknowledgements, retransmissions and flow control to support reliable communication. It is commonly used for web browsing, file transfers and email.

UDP (User Datagram Protocol):
UDP is connectionless and sends independent datagrams without establishing a connection.

Its characteristics include:
- No connection handshake.
- No guaranteed delivery or packet ordering.
- No built-in retransmission.
- Lower overhead than TCP.

UDP is useful for online gaming, voice calls, live streaming and DNS queries, where low latency is important.

TCP AND UDP COMPARISON

TCP:
- Connection-oriented.
- Reliable and ordered delivery.
- Uses acknowledgements and retransmissions.
- Minimum header size: 20 bytes.

UDP:
- Connectionless.
- Delivery and ordering are not guaranteed.
- No built-in retransmission.
- Header size: 8 bytes.

4. DOMAIN NAME SYSTEM (DNS)

The Domain Name System translates human-readable domain names into IP addresses so that devices can locate websites and other network services.

DNS Resolution Process:
1. A client requests the IP address of a domain name.
2. A recursive resolver receives the request.
3. If the answer is not cached, it queries a Root Nameserver.
4. The root server directs it to the appropriate Top-Level Domain (TLD) server.
5. The TLD server directs it to the authoritative nameserver.
6. The authoritative nameserver provides the requested DNS record.
7. The resolver returns the result to the client and may cache it.

Common DNS Records:
- A Record: Maps a domain name to an IPv4 address.
- AAAA Record: Maps a domain name to an IPv6 address.
- CNAME Record: Creates an alias for another domain name.
- MX Record: Identifies the mail servers responsible for receiving email.

DNS caching stores previously obtained records temporarily. The TTL value specifies how long a record can remain in the cache before it should be refreshed.

5. SUMMARY

The OSI model explains communication through seven layers. The Network Layer manages IP addressing and routing. The Transport Layer provides communication through TCP and UDP. TCP supports reliable, ordered delivery, while UDP offers connectionless communication with lower overhead. DNS translates domain names into IP addresses through a hierarchical resolution process.
